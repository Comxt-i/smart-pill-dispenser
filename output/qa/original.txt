คำนำ
รายงานฉบับนี้นำเสนอการออกแบบและพัฒนาเครื่องจ่ายยาอัจฉริยะสำหรับช่วยจัดการยาตามเวลาที่กำหนด โดยใช้ไมโครคอนโทรลเลอร์ ESP32 ควบคุมกลไกจานหมุนสามช่อง ทำงานร่วมกับเว็บไซต์สำหรับกำหนด ตารางยาและตรวจสอบประวัติการจ่ายยา โครงงานมุ่งเชื่อมโยงความรู้ด้านระบบฝังตัว การควบคุมอุปกรณ์และ การสื่อสารผ่านเครือข่ายเข้าด้วยกัน
เนื้อหาประกอบด้วยที่มาและวัตถุประสงค์ เทคโนโลยีที่ใช้ วัสดุอุปกรณ์ การออกแบบฮาร์ดแวร์และ ซอฟต์แวร์ ตลอดจนผลการทดสอบและข้อเสนอแนะในการพัฒนาต่อ ระบบใช้จอแสดงผลและเสียงเตือนเพื่อ แจ้งรอบยา ผู้ใช้สามารถกดรับยา เลื่อนการเตือน หรือข้ามรอบยา และระบบส่งผลการทำงานกลับไปยังเว็บไซต์
การพัฒนาซอฟต์แวร์ครอบคลุมการนับเม็ดยาด้วยเซ็นเซอร์ IR การจัดคิวหลายช่อง การเก็บเหตุการณ์ เมื่อเครือข่ายขัดข้อง และการตั้งค่า Wi-Fi ผ่านโทรศัพท์ ผลทดสอบซอฟต์แวร์ช่วยตรวจสอบตรรกะของระบบ ส่วนการประเมินความแม่นยำของกลไกต้องดำเนินการกับอุปกรณ์และเม็ดยาจริงเพิ่มเติม
คณะผู้จัดทำหวังว่ารายงานฉบับนี้จะเป็นประโยชน์ต่อผู้ที่สนใจพัฒนาระบบจ่ายยาและประยุกต์ใช้ อินเทอร์เน็ตของสรรพสิ่งในงานระบบฝังตัว

บทที่ 1  บทนำ
1.1 ที่มาและความสำคัญ
การจัดยาหลายชนิดให้ตรงตามตารางเป็นงานที่ต้องติดตามทั้งเวลาและจำนวนเม็ด โดยเฉพาะเมื่อผู้ใช้งาน มีรอบยาหลายช่วงในหนึ่งวัน โครงงานนี้จึงพัฒนาอุปกรณ์ช่วยเตือนและจ่ายยาตามข้อมูลที่กำหนดไว้บนเว็บไซต์ เพื่อให้ผู้ใช้และผู้ดูแลตรวจสอบการทำงานของเครื่องได้จากประวัติที่บันทึกไว้
เครื่องจ่ายยาอัจฉริยะใช้ ESP32 เพียงบอร์ดเดียวควบคุมจานยาสามชุด เมื่อถึงเวลาจะส่งเสียงเตือนและ แสดงรายการยา ผู้ใช้กดปุ่มรับยาเพื่อเริ่มกลไก และเซ็นเซอร์ IR ตรวจนับเม็ดยาที่ผ่านทางออก ผลการจ่ายจะถูก ส่งกลับไปยังเซิร์ฟเวอร์ หากเครือข่ายขัดข้องระหว่างใช้งาน เครื่องยังสามารถใช้ตารางของวันที่รับไว้ในหน่วย ความจำและรอส่งเหตุการณ์ภายหลัง
1.2 วัตถุประสงค์
1. เพื่อออกแบบต้นแบบเครื่องจ่ายยาสามช่องที่ควบคุมด้วย ESP32 และรับตารางจากเว็บไซต์
2. เพื่อพัฒนาการเตือน การรับยา การเลื่อนเตือน และการบันทึกผลของแต่ละรอบยา
3. เพื่อใช้เซ็นเซอร์ IR ตรวจนับยาและจัดการกรณีจ่ายไม่ครบหรือเซ็นเซอร์ถูกบัง
4. เพื่อทดสอบตรรกะการทำงานร่วมกันของกลไก ตารางเวลา และการสื่อสารกับเซิร์ฟเวอร์
1.3 ขอบเขตของโครงงาน
รองรับยาแยกสามช่อง ช่องละหนึ่งชนิด สูงสุดหกรอบต่อวันต่อช่อง และคำสั่งครั้งละ 1–9 เม็ดตามค่ากำหนด ในเฟิร์มแวร์ จ่ายพร้อมกันได้สูงสุดสองช่อง ส่วนช่องที่เหลือรอคิว ระบบรายงานสถานะการจ่ายของเครื่อง ว่าผู้ใช้ รับประทานยาแล้วหรือไม่ ขนาดเม็ดยา ตำแหน่งจาน และค่าขับมอเตอร์ผ่านการสอบเทียบก่อนใช้โหมดกลไกจริง
บทที่ 2  เอกสารและเทคโนโลยีที่เกี่ยวข้อง
2.1 ไมโครคอนโทรลเลอร์ ESP32
ESP32 เป็นศูนย์กลางของระบบ ทำหน้าที่เชื่อมต่อ Wi-Fi รับข้อมูลจากเซิร์ฟเวอร์ ประมวลผลตารางยา และควบคุมอุปกรณ์ผ่านขา GPIO โครงงานกำหนดผังขาสำหรับบอร์ด ESP32 DevKit หรือ ESP32-WROOM-32 แบบดั้งเดิม และใช้ในการสั่งจานยา

2.2 นาฬิกา DS1307 และจอ LCD
ระบบอ่านเวลาจาก DS1307 ผ่านบัส I²C และปรับเวลาจากข้อมูลเซิร์ฟเวอร์ จอ LCD ขนาด 16×2 ใช้แสดงวันที่และเวลา ส่วนจอ 20×4 แสดงรายการยาและคำแนะนำปุ่ม ค่าเริ่มต้นของที่อยู่ I²C คือ 0x25 และ 0x27 ตามลำดับ ชื่อยาบนจอใช้อักษภาษาอังกถษตามรูปแบบข้อมูลที่เซิร์ฟเวอร์ส่งมา

2.3 เซอร์โวมอเตอร์และมอเตอร์สั่น
กลไกแต่ละช่องประกอบด้วยเซอร์โวมอเตอร์ขับจานและมอเตอร์สั่นช่วยให้เม็ดยาเคลื่อนผ่านทางออก โปรแกรมกำหนดตำแหน่งพักและตำแหน่งปล่อยด้วยความกว้างพัลส์ จึงต้องใช้ค่าที่สอบเทียบกับเซอร์โว และจานจริง มอเตอร์สั่นสามตัวควบคุมผ่าน DRV8833 สองบอร์ด โดยใช้เอาต์พุตสามช่องจากสี่ช่องที่มี
2.4 เซ็นเซอร์ IR สำหรับตรวจนับเม็ดยา
แต่ละจานมีเซ็นเซอร์ IR หนึ่งตัว โปรแกรมจะมีช่วงพักการนับ 60 มิลลิวินาที เพื่อลดการนับซ้ำ นับเฉพาะ ช่องที่เริ่มจ่ายแล้ว และหยุดเมื่อครบจำนวนที่สั่ง ถ้าเซ็นเซอร์ถูกบังก่อนเริ่ม ระบบจะปฏิเสธการเริ่มจ่ายช่องนั้น การตรวจจับในซอฟต์แวร์ยังต้องประเมินกับระยะติดตั้ง แสงแวดล้อม และรูปร่างเม็ดยาจริง


บทที่ 2  เอกสารและเทคโนโลยีที่เกี่ยวข้อง
2.5 การสื่อสารผ่านเครือข่ายและ API
ESP32 เป็นฝ่ายร้องขอข้อมูลจากเซิร์ฟเวอร์เป็นระยะ โดยปกติทุก 60 วินาที การร้องขอ GET /api/device/sync ใช้รับเวลา ตารางยาของวันปัจจุบัน และคำสั่งที่รอดำเนินการ ส่วน POST /api/device/events ใช้ส่งผลกลับ การตอบรับคำสั่งเริ่มจ่ายและผลการจ่ายเสร็จเป็นคนละขั้นตอน จึงต้องติดตามผลจากเหตุการณ์ที่เครื่องรายงาน
เฟิร์มแวร์รองรับ URL แบบ HTTP และ HTTPS เมื่อใช้ HTTPS จะตรวจใบรับรองตามค่าที่เปิดไว้ใน config.h การยืนยันตัวตนของอุปกรณ์ใช้ API key เฉพาะเครื่อง ส่วนเว็บไซต์ใช้บัญชีผู้ใช้และ JWT ข้อมูลรหัสผ่านและกุญแจของอุปกรณ์ไม่ควรปรากฏในรายงานหรือภาพตัวอย่าง
2.6 เว็บไซต์และฐานข้อมูล
ส่วนเว็บไซต์ใช้ React และ TypeScript ส่วนบริการฝั่งเซิร์ฟเวอร์ใช้ NestJS และ Prisma เชื่อมต่อ PostgreSQL โครงสร้างข้อมูลหลักประกอบด้วยบัญชีผู้ใช้ อุปกรณ์ ช่องยา รายการยา ตารางเวลา ประวัติผลการจ่าย และคำสั่งอุปกรณ์ ข้อมูลเหล่านี้ทำให้การตั้งตารางและตรวจสอบผลผูกกับอุปกรณ์และ เจ้าของข้อมูลหรือ account ที่สร้าง
2.7 การทำงานแบบสถานะและการเก็บข้อมูลถาวร
โปรแกรมแยกสถานะรอบยา เช่น รอเวลา เตือน เลื่อนเตือน รอคิว กำลังจ่าย สำเร็จ ข้าม ขาดรอบ และ ล้มเหลว การควบคุมเซอร์โวเปลี่ยนสถานะตามเวลาโดยไม่ใช้การหน่วงรอในขั้นตอนการเคลื่อนที่ ทำให้ loop หลักตรวจปุ่มและอัปเดตหน้าจอต่อได้ 
Flash/NVS ใช้เก็บค่าตั้งเครือข่าย คิวเหตุการณ์ และคำสั่งที่รับจาก website ไว้แล้ว การจองรหัสคำสั่ง (Command ID) ก่อนเริ่ม เพื่อช่วยลดการทำซ้ำเมื่อคำสั่งถูกส่งใหม่หรืออุปกรณ์เริ่มทำงานใหม่ ถ้าจองรายการไม่ได้ ระบบจะไม่เริ่มกลไก การเก็บคิวเหตุการณ์มีขนาดจำกัดจึงต้องสั่งล้างคิวเก่า และมีการเตือนเมื่อเน็ตดับนานเกินไป

3.3 การออกแบบกลไกและการนับเม็ดยา
ชุดจ่ายแต่ละช่องเริ่มจากตำแหน่งพัก เมื่อรับคำสั่งที่ผ่านการตรวจสอบแล้ว โปรแกรมสั่งเซอร์โวไปตำแหน่งปล่อย กลับตำแหน่งพัก และสั่นต่อเพื่อช่วยให้ยาผ่านทางออก ลำดับสถานะคือ  Idle → WaitingStart → Releasing → Returning → Shaking  แล้วตรวจว่าจะทำรอบต่อหรือสิ้นสุด

3.5 เว็บไซต์และการแลกเปลี่ยนข้อมูล

ลำดับการรับและส่งข้อมูล
1. กล่องยาทักหาเซิร์ฟเวอร์: ESP32 ส่งข้อความไปขออัปเดตข้อมูล พร้อมแนบรหัสยืนยันตัวตนและเวอร์ชันโปรแกรมของเครื่อง 
2. เซิร์ฟเวอร์ส่งข้อมูลกลับ: เซิร์ฟเวอร์จะส่งเวลาปัจจุบัน ตารางยากลับมาให้ รวมถึงคำสั่งที่ค้างอยู่ แล้วกล่องยาจะตรวจความถูกต้องก่อนดึงไปใช้งาน 
3. กล่องยาบันทึกผล: เมื่อหมุนจ่ายยาเสร็จ กล่องยาจะสร้างรายงานผลขึ้นมา โดยใส่รหัสอ้างอิงเฉพาะ ช่องยาที่จ่าย จำนวนเม็ด สถานะ และเวลาที่เกิดขึ้น 
4. ส่งรายงานและลบคิว: กล่องยาส่งรายงานกลับไปหาเซิร์ฟเวอร์ พอเซิร์ฟเวอร์ได้รับและบันทึกเรียบร้อย กล่องยาจะลบรายงานนั้นออกจากคิวความจำ โดยรหัสรายงานจะช่วยป้องกันไม่ให้บันทึกประวัติซ้ำ หากมีการส่งข้อมูลซ้ำ 
ความหมายของผลที่ส่งกลับ
DISPENSED DISPENSED: หมายถึงระบบประเมินว่าการจ่ายยาสำเร็จตามโหมดที่ใช้งาน   
MISSED: หมายถึงพ้นกำหนดเวลาผ่อนผัน   
SKIPPED: หมายถึงผู้ใช้เลือกกดข้ามรอบยานั้น   
FAILED: หมายถึงการจ่ายยาไม่สำเร็จหรือมีข้อขัดข้องเกิดขึ้น   
Dry Run: ระบบจะแนบข้อความ dry run เพื่อแยกแยะออกจากการจ่ายยาด้วยกลไกจริง และการที่ระบบรายงานว่าจ่ายยาสำเร็จยังไม่เท่ากับการยืนยันว่าผู้ป่วยได้ทำการรับประทานยาจริง   
3.6 การตั้งค่าและการจัดการเมื่อเกิดข้อขัดข้อง
การตั้งค่า Wi-Fi และจับคู่บัญชี
เริ่มจากสแกน QR ของอุปกรณ์แล้วเข้าสู่ระบบบนเว็บไซต์เพื่อสร้างรหัสตั้งค่าชั่วคราว จากนั้นเชื่อมโทรศัพท์กับเครือข่ายตั้งค่าของกล่อง เปิดหน้า 192.168.4.1 เลือกเครือข่ายบ้านและกรอกรหัสตั้งค่า เครื่องตรวจการเชื่อมต่อและยืนยันกับเซิร์ฟเวอร์ก่อนบันทึกค่า เมื่อสำเร็จจึงปิดเครือข่ายตั้งค่าและกลับเข้าสู่การทำงานปกติ
กรณีต้องเปลี่ยนเครือข่าย ผู้ใช้กดปุ่มเขียวค้างสามวินาทีขณะกลไกว่าง ระหว่างตั้งค่าระบบพักการจ่ายและการเตือน การหลุดจากเราเตอร์ชั่วคราวไม่ลบรหัสผ่านเดิมและไม่ควรเปลี่ยนเจ้าของอุปกรณ์โดยอัตโนมัติ

การทำงานเมื่อเครือข่ายขัดข้อง
หากอุปกรณ์ยังทำงานและมีตารางของวันนี้อยู่ในหน่วยความจำ สามารถเตือนและประมวลผลรอบยาจากข้อมูลล่าสุดได้ เหตุการณ์จะรอส่งใน NVS คิวปัจจุบันรองรับ 12 รายการและทิ้งรายการเก่าสุดเมื่อเต็ม จึงยังมีความเสี่ยงต่อประวัติสูญหายเมื่อออฟไลน์นาน
การเริ่มเครื่องใหม่และการป้องกันการจ่ายซ้ำ
การกู้คิวผลจาก NVS เป็นคนละเรื่องกับการกู้ตารางยา ตารางทำงานอยู่ในหน่วยความจำและต้องรับข้อมูลจากเซิร์ฟเวอร์หลังเริ่มเครื่องใหม่ จึงไม่ควรถือว่าการมี RTC สำรองทำให้พร้อมจ่ายหลังไฟดับโดยไม่มีเครือข่ายเสมอไป ทะเบียนคำสั่งที่จองก่อนกลไกเริ่มทำงานช่วยปฏิเสธคำสั่งเดิมที่ส่งซ้ำ แต่กรณีไฟดับกลางรอบยังต้องตรวจจำนวนยาที่ออกจริง
การเตรียมเครื่องก่อนเปิดกลไกจริง
ทดสอบแต่ละช่องโดยไม่ใส่ยาก่อน ตรวจตำแหน่งพักและปล่อย ขาเซ็นเซอร์ และการหยุด จากนั้นกำหนด PILLBOX_REAL_HARDWARE และ PILLBOX_CALIBRATED พร้อมค่าพัลส์ที่สอบเทียบแล้ว ค่าเริ่มต้นของโปรไฟล์ที่ไม่มีไฟล์ปรับแต่งเป็นโหมดจำลอง การเปลี่ยนเป็นกลไกจริงต้องตรวจการจ่ายร่วมกับ IR และแหล่งจ่ายทุกครั้ง

บทที่ 5  สรุปผลและข้อเสนอแนะ
5.1 สรุปผลการพัฒนา
โครงงานเครื่องจ่ายยาอัจฉริยะได้พัฒนาซอฟต์แวร์สำหรับควบคุมจานยาสามช่องด้วย ESP32 เชื่อมการตั้งตารางบนเว็บไซต์เข้ากับการเตือน การรับยา การนับเม็ดด้วยแสงเลเซอร์ และการบันทึกผลกลับไปยังเซิร์ฟเวอร์ ระบบจัดคิวให้ทำงานพร้อมกันได้ไม่เกินสองช่อง 
เฟิร์มแวร์มีการจัดการข้อมูลระหว่างเครือข่ายขัดข้อง การตรวจคำสั่งซ้ำ และการตั้งค่าเครือข่ายผ่านโทรศัพท์ ชุดทดสอบซอฟต์แวร์ 13 รายการผ่านทั้งหมด ผลนี้แสดงความคืบหน้าด้านตรรกะของระบบ ส่วนความแม่นยำการจ่ายและความพร้อมใช้งานของต้นแบบต้องอาศัยผลทดลองทางกายภาพประกอบ
5.2 ข้อจำกัด
ข้อจำกัดสำคัญ ได้แก่ การสอบเทียบให้เหมาะกับขนาดและผิวของเม็ดยา ความคลาดเคลื่อนของเลเซอร์ เมื่อยาเคลื่อนติดกัน ความสามารถของแหล่งจ่ายเมื่อขับหลายช่อง และเวลาตอบสนองระหว่างคำขอเครือข่าย คิวเหตุการณ์เก็บได้ 12 รายการและอาจทิ้งประวัติเก่าสุดเมื่อเต็ม ส่วนตารางยาไม่ใช่ข้อมูลสำรองถาวรสำหรับเริ่มเครื่องโดยไม่มีเครือข่าย
หน้าจอแสดงชื่อยาเป็นภาษาอังกฤษ และสถานะการจ่ายยาของเครื่องไม่ยืนยันการรับประทานของผู้ใช้ การสั่งจากเว็บไซต์มีช่วงรอการซิงก์ อีกทั้งการหยุดจากซอฟต์แวร์ไม่ทดแทนการตัดกำลังของกลไกโดยตรง
5.3 แนวทางพัฒนาต่อ
ควรเริ่มจากการทดลองจ่ายจริงแยกแต่ละช่องและหลายช่อง วัดจำนวนเม็ด เวลาจ่าย และกระแสสูงสุด แล้วปรับค่าจานและ IR จากข้อมูลนั้น ถัดมาควรเพิ่มการจัดการคิวเต็มโดยไม่ทิ้งผลเงียบ ๆ พิจารณาสำรองตารางพร้อมตรวจวันหมดอายุของข้อมูล และทดสอบการกู้ระบบหลังไฟดับกลางรอบ
ด้านการใช้งาน ควรทดลองกับผู้ใช้เป้าหมายเพื่อประเมินความชัดเจนของปุ่ม ข้อความ และเสียงเตือน รวมทั้งจัดทำคู่มือเติมยา ทำความสะอาด และตรวจเครื่องก่อนใช้งาน การประเมินเหล่านี้จะช่วยกำหนดขอบเขตการใช้งานของต้นแบบได้จากหลักฐานจริง
