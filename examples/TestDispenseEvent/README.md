# TestDispenseEvent — ทดสอบการยิงผลการกดรับยาขึ้น server

sketch แยกสำหรับตรวจว่าเส้นทาง **ESP32 → backend** ใช้งานได้จริง
โดยไม่ต้องต่อ LCD, RTC, Servo หรือกลไกใดๆ — ต่อแค่บอร์ดกับสาย USB ก็ทดสอบได้

ใช้ตอนไล่ปัญหาว่า "กล่องยาไม่ส่งข้อมูลขึ้นเว็บ" เกิดจาก network/auth หรือจากตัวกลไก

## เตรียมก่อนใช้

1. คัดลอก `secrets.example.h` เป็น `secrets.h` ในโฟลเดอร์นี้ แล้วกรอก Wi-Fi,
   `SERVER_BASE_URL` และ `DEVICE_API_KEY`
2. ติดตั้งไลบรารี **ArduinoJson v7 ขึ้นไป** (ไลบรารีอื่นไม่ต้องใช้ในการทดสอบนี้)
3. ต่อปุ่มจาก **GPIO33 ลง GND** — ไม่มีปุ่มก็สั่งผ่าน Serial Monitor ได้
4. เปิด `TestDispenseEvent.ino` ใน Arduino IDE แล้วอัปโหลด
5. เปิด Serial Monitor ที่ **115200 baud**

## สิ่งที่ sketch ทำตอนบูต

```text
1. เชื่อม Wi-Fi                     -> พิมพ์ IP และความแรงสัญญาณ
2. ตั้งนาฬิกาจาก NTP (เฉพาะ https)   -> จำเป็นเพราะ TLS ตรวจอายุใบรับรอง
3. GET /api/device/sync             -> พิมพ์ตารางยาของวันนี้ทั้งหมด
4. เลือกมื้อแรกที่ยังไม่ได้จ่ายเป็นเป้าหมาย -> event ที่ส่งจะผูกกับมื้อยาจริง
```

## คำสั่งทดสอบ

| สั่ง | ผล |
|---|---|
| กดปุ่ม GPIO33 หรือพิมพ์ `d` | ส่ง `DISPENSED` (จ่ายยาสำเร็จ) |
| `m` | ส่ง `MISSED` (ขาดยา) |
| `s` | ส่ง `SKIPPED` (ผู้ใช้กดข้าม) |
| `f` | ส่ง `FAILED` (จ่ายไม่สำเร็จ) |
| `x` | **ส่ง event เดิมซ้ำ** — server ต้องตอบ accepted แต่ประวัติในเว็บต้องไม่เพิ่ม |
| `r` | ดึงตารางยาใหม่ |
| `h` | แสดงเมนู |

คำสั่ง `x` คือตัวพิสูจน์กลไกกันบันทึกซ้ำ: firmware จริงจะส่ง event ซ้ำเมื่อเน็ตหลุด
ตอนขากลับ ระบบจึงต้องไม่สร้างประวัติซ้ำ ลองกด `d` แล้วตามด้วย `x` หลายครั้ง
แล้วเปิดหน้าประวัติในเว็บดู — ต้องมีรายการเพิ่มแค่รายการเดียว

## ตัวอย่างผลลัพธ์ที่ถูกต้อง

```text
[event] POST http://192.168.1.100:3000/api/device/events
[event] ส่ง: {"events":[{"event_id":"A1B2C3-1","status":"DISPENSED",...}]}
[event] HTTP 200 (ใช้เวลา 84 ms)
[event] ตอบกลับ: {"ok":true,"received":1,"accepted":["A1B2C3-1"],"rejected":[]}
        รับแล้ว: A1B2C3-1
```

## อ่านผลเมื่อมีปัญหา

| สิ่งที่เห็นใน Serial | สาเหตุ |
|---|---|
| `HTTP 401` | `DEVICE_API_KEY` ไม่ตรงกับ `Device.api_key` ในฐานข้อมูล |
| `HTTP 400` | JSON ไม่ผ่าน validation ของ server (ดูข้อความที่ตอบกลับ) |
| `HTTP -1` | ต่อไม่ถึง server, IP ผิด, firewall บล็อก หรือใบรับรองไม่ตรงกับ `certs.h` |
| `ถูกปฏิเสธ: ... ไม่พบยาที่ตรงกับช่อง` | ช่องนั้นยังไม่ได้ใส่ยาในหน้าเว็บ |
| ค้างที่ `[NTP] กำลังขอเวลา...` | เครือข่ายบล็อก UDP port 123 — ลองใช้ `http://` ในวง LAN แทน |
| `[Wi-Fi] เชื่อมต่อไม่สำเร็จ` | SSID/รหัสผ่านผิด หรือเป็น Wi-Fi 5GHz (ESP32 รองรับแค่ 2.4GHz) |

## ข้อควรรู้

- sketch นี้ **ไม่ขยับ Servo** และไม่แตะกลไกใดๆ ส่งข้อมูลอย่างเดียว
- event ที่ส่งจะถูกบันทึกเป็นประวัติจริงในฐานข้อมูล ถ้าไม่อยากให้ปนกับข้อมูลจริง
  ให้ทดสอบกับ backend ที่รันในเครื่องตัวเองก่อน
- ถ้าส่ง `DISPENSED` ตอนที่เลยเวลามื้อยาเกิน 30 นาที **server จะบันทึกเป็น `TAKEN_LATE` ให้เอง**
  ซึ่งเป็นพฤติกรรมที่ถูกต้อง ไม่ใช่ข้อผิดพลาด

รายละเอียดของ API ทั้งหมดอยู่ใน [docs/SERVER_API.md](../../docs/SERVER_API.md)
