# Smart Pill Dispenser

โปรเจกต์กล่องยาสำหรับผู้สูงอายุแบบจานหมุน 3 ชุด ใช้ **ESP32 เพียงบอร์ดเดียว**
ทำงานร่วมกับเว็บ (`embedded_project/`) ซึ่งเป็นที่ตั้งตารางยาและเก็บประวัติการจ่ายยา

- ESP32 ควบคุม Wi-Fi, RTC DS1307, LCD 2 จอ, ปุ่มกด, Buzzer และ Servo 270° จำนวน 3 ตัวโดยตรง
- Servo แต่ละตัวหมุนจานของยาคนละชนิด ไม่ใช่ระบบรางยา 3 ชุด
- **ตารางยามาจากเว็บอัตโนมัติ** เครื่องดึงเองทุก 60 วินาที ไม่ต้องตั้งค่าที่ตัวเครื่อง
- **ผลการจ่ายยาถูกส่งกลับขึ้นเว็บทุกครั้ง** และมีคิวใน NVS สำหรับส่งใหม่เมื่อเน็ตหลุด
- มี IR จำนวน 3 ตัวสำหรับตรวจเม็ดยาที่ตกจากจานยา จานละ 1 ตัว; ยังรอยืนยันรุ่นและเพิ่มโค้ดอ่านค่า
- ไม่มีบอร์ด Nano หรือ protocol ส่งคำสั่งระหว่างบอร์ด

## การทำงานหนึ่งรอบ

```text
1. เว็บ: ผู้ใช้เพิ่มยา ตั้งเวลา และเลือกใส่ยาลงช่องที่ 1–3
2. ESP32: GET /api/device/sync ทุก 60 วินาที -> ตั้ง RTC + รับตารางยาของวันนี้
3. ถึงเวลามื้อยา: Buzzer เตือน + LCD จอที่ 2 แสดงชื่อยา เวลา และจำนวนเม็ด
4. ผู้ใช้กดปุ่ม Dispense (GPIO33) -> จานหมุนจ่ายยา
5. ESP32: POST /api/device/events -> เว็บเห็นผลในประวัติและหน้าตารางทันที
6. ถ้าไม่มีใครกดภายใน 30 นาที -> บันทึกเป็น "ขาดยา" อัตโนมัติ
```

รายละเอียดของ API ทั้งหมดอยู่ใน [docs/SERVER_API.md](docs/SERVER_API.md)

## ปุ่มกด

| ปุ่ม | GPIO | กดขณะกำลังเตือน | กดตอนปกติ |
|---|---:|---|---|
| Dispense | 33 | จ่ายยามื้อนั้น | เตือนว่ายังไม่ถึงเวลา |
| Confirm | 32 | ยืนยันว่าทานเองแล้ว (ปิดการเตือน + บันทึกว่าจ่ายแล้ว) | สั่ง sync ตารางใหม่ทันที |
| Cancel | 27 | กดสั้น = ข้ามมื้อนี้ (บันทึกเป็น SKIPPED) | — |
| Cancel (กดค้าง ≥ 1.2 วินาที) | 27 | หยุดส่ง PWM ทันที | หยุดส่ง PWM ทันที |

การหยุด PWM ไม่ใช่การตัดไฟ Servo หรือการรับประกันว่ากลไกหยุดทันที

## บอร์ดและไลบรารีที่ต้องใช้

ผังขาเริ่มต้นอิง ESP32 DevKit / ESP32-WROOM-32 แบบดั้งเดิม ไม่ใช่ ESP32-C3/S3
ติดตั้งแพ็กเกจบอร์ด `esp32 by Espressif Systems` และเลือกบอร์ดให้ตรงกับฮาร์ดแวร์
ติดตั้งไลบรารี:

- `ESP32Servo` สำหรับควบคุม Servo ด้วย PWM ของ ESP32
- `ArduinoJson` **เวอร์ชัน 7 ขึ้นไป** (โค้ดใช้ `JsonDocument` แบบใหม่ ไม่รองรับ v6)
- `LiquidCrystal_I2C`
- `TimeLib` (ชื่อใน Library Manager: `Time`)
- `DS1307RTC`

`Wire`, `WiFi`, `WebServer`, `HTTPClient` และ `Preferences` มาพร้อมแพ็กเกจบอร์ด ESP32

## ตั้งค่าก่อนใช้งาน

1. **เตรียม backend ให้พร้อมก่อน** เลือกอย่างใดอย่างหนึ่ง:
   - *ทดสอบในวง LAN*: ที่ `embedded_project/backend` คัดลอก `.env.example` เป็น `.env`
     แล้วรัน `npm install`, `npm run prisma:db:push`, `npm run prisma:seed`, `npm start`
     backend ผูกกับ `0.0.0.0` อยู่แล้ว จึงเรียกจากวง LAN ได้
   - *ใช้งานจริงผ่านอินเทอร์เน็ต*: deploy ด้วย Docker Compose ตาม
     [embedded_project/DEPLOY.md](../embedded_project/DEPLOY.md) จะได้โดเมนพร้อม HTTPS
2. คัดลอก `ESP32_Main/secrets.example.h` เป็น `ESP32_Main/secrets.h` แล้วกรอก:
   - `WIFI_SSID` / `WIFI_PASSWORD`
   - `SERVER_BASE_URL` — รองรับทั้งสองแบบ:
     - deploy แล้ว: `https://pillbox.example.com` (ตรวจใบรับรองด้วย `certs.h` ให้อัตโนมัติ)
     - ในวง LAN: `http://192.168.1.100:3000` โดยใช้ IP ของเครื่องที่รัน backend
       ห้ามใช้ `localhost` เพราะ localhost ของ ESP32 คือตัวมันเอง
   - `DEVICE_API_KEY` = ค่าจาก `Device.api_key` ในฐานข้อมูล
     (seed ตอน dev ให้ค่า `esp32_sec_key_246f28abc199` ส่วนตอน production จะสุ่มให้ใหม่)
3. ต่อสายตาม [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md): Servo จาน 1–3 ใช้ GPIO18, GPIO19, GPIO23
4. ตรวจ I²C address ของ LCD ทั้งสองจอ; ค่าเริ่มต้นคือ `0x27` และ `0x25` ส่วน DS1307 คือ `0x68`
5. ตรวจช่วง pulse ที่ Servo รองรับ แล้วปรับ `SERVO_MIN_PULSE_US`, `SERVO_MAX_PULSE_US`,
   `REST_PULSE_US`, `RELEASE_PULSE_US` และ `MOVE_TIME_MS` ใน `config.h` โดยทดสอบแบบไม่ใส่ยาก่อน
   ค่าเริ่มต้นเป็นเพียงตัวอย่าง ไม่ใช่ช่วงหมุนครบ 270°
6. เปลี่ยน `ENABLE_SERVO_MOVEMENT` เป็น `true` และอัปโหลดใหม่เมื่อพร้อมทดสอบการเคลื่อนไหว
   **ค่าเริ่มต้น `false` จะปฏิเสธคำสั่งจ่ายทุกครั้งโดยไม่จ่าย PWM** และจะรายงานกลับเว็บว่า
   `FAILED / servo disabled` ซึ่งเป็นพฤติกรรมที่ถูกต้อง ไม่ใช่ความผิดพลาดของการเชื่อมต่อ
7. เปิด Serial Monitor ที่ 115200 baud แล้วเปิด IP ที่แสดงหลังเชื่อมต่อ Wi-Fi
   เพื่อดูหน้าสถานะในเครื่อง (ตาราง สถานะ sync คิวที่ค้าง และปุ่มทดสอบจ่ายยา)

## ทดสอบการเชื่อมต่อก่อนประกอบกลไก

ถ้าอยากตรวจว่า ESP32 คุยกับ server ได้จริงก่อนจะต่อ LCD, RTC และ Servo
ให้อัปโหลด [examples/TestDispenseEvent](examples/TestDispenseEvent/) แทน
sketch นั้นต่อแค่บอร์ดกับสาย USB ก็ทดสอบได้ ใช้ไลบรารีแค่ ArduinoJson
และมีคำสั่งผ่าน Serial สำหรับยิง `DISPENSED` / `MISSED` / `SKIPPED` / `FAILED`
รวมถึงทดสอบการส่งซ้ำเพื่อพิสูจน์ว่าระบบกันบันทึกซ้ำได้จริง

## พฤติกรรมเมื่อเน็ตหรือไฟมีปัญหา

- **Wi-Fi หลุด**: นาฬิกา ปุ่มกด เสียงเตือน และการจ่ายยายังทำงานต่อจากตารางที่ดึงไว้ล่าสุด
  ผลการจ่ายยาถูกเก็บในคิวและส่งเมื่อกลับมาออนไลน์
- **ไฟดับ**: คิวผลการจ่ายยาถูกเก็บใน NVS จึงไม่หาย และ DS1307 ที่มีถ่านสำรองยังเดินเวลาต่อ
- **บูตกลางวัน**: มื้อที่เลยมาเกิน 30 นาทีจะถูกข้ามเงียบๆ ไม่ปลุกย้อนหลังและไม่รายงานซ้ำ
  เพราะฝั่ง server ถือว่ามื้อที่ไม่มี log คือขาดยาอยู่แล้ว
- **server ล่ม**: เครื่องลองใหม่ทุก 15 วินาที และยังทำงานตามตารางเดิมระหว่างนั้น

## ทดสอบ logic บนคอมพิวเตอร์

ต้องมี `c++` และ `python3`

```bash
python3 tests/test_dispenser_control.py
python3 tests/test_schedule_store.py
python3 tests/test_firmware_syntax.py
```

- `test_dispenser_control.py` ทดสอบการคุม Servo ด้วยฮาร์ดแวร์จำลอง ทั้งตอนเปิดและปิดการเคลื่อนไหว
  รวมถึงการรายงานผลหนึ่งรอบผ่าน `takeDispenseOutcome()`
- `test_schedule_store.py` ทดสอบตรรกะตารางยา: การเตือน การนับว่าขาดยา การข้ามมื้อที่เลยมานานตอนบูต
  การคงสถานะเมื่อ sync ระหว่างวัน การข้ามวัน และช่องที่ถูกปิดใช้งาน
- `test_firmware_syntax.py` ตรวจไวยากรณ์ของทุกโมดูล **รวมถึง sketch ใน `examples/`**
  ด้วย header จำลองใน `tests/syntax/` จับพวกพิมพ์ผิด ลืม include และเรียกฟังก์ชันผิด
  signature ได้โดยไม่ต้องมี ESP32 toolchain

การทดสอบเหล่านี้ **ไม่แทน** การ compile ด้วย ESP32 toolchain จริงหรือการทดสอบกับบอร์ดและกลไกจริง
`tests/syntax/` เป็น header จำลองแบบว่างเปล่า ไม่ได้ตรวจพฤติกรรมของไลบรารีจริง
ก่อนนำไปใช้งานจริงต้อง compile และอัปโหลดผ่าน Arduino IDE เสมอ

## ระบบจ่ายไฟ

- ใช้ Adapter 5V regulated ต่อผ่าน Fuse และสวิตช์ก่อนเข้าบอร์ดกระจายไฟ
- ต่อ Capacitor 1000µF คร่อม `+5V` กับ `GND` ใกล้จุดจ่ายไฟ Servo
- จ่ายไฟ Servo จากบอร์ดกระจายไฟโดยตรง ห้ามจ่ายผ่านขา 3.3V/5V ของ ESP32
- ESP32, Servo และโมดูลที่สื่อสารกันต้องใช้ GND ร่วมกัน
- ตรวจว่า Servo รองรับ 5V และเลือกพิกัด Fuse ตามสาย ขั้วต่อ และกระแสจริงของระบบ
- GPIO ของ ESP32 ใช้ลอจิก 3.3V: โมดูล I²C ที่ดึงสัญญาณขึ้น 5V ยังต้องผ่าน Logic Level Shifter

รายละเอียดระดับสัญญาณ ผังสาย และข้อจำกัด firmware อยู่ใน [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)

## สิ่งที่ยังไม่ได้ทำ

- **IR ยังไม่ถูกอ่าน**: จำนวนที่สั่งยังเป็นจำนวนรอบขยับ Servo ไม่ใช่จำนวนเม็ดที่ตรวจยืนยันแล้ว
  สถานะ `DISPENSED` จึงหมายถึง "จานหมุนครบรอบ" ไม่ใช่ "เม็ดยาตกครบจำนวน"
- ค่า pulse และเวลาหมุนยังไม่ผ่านการสอบเทียบกับกลไกจริง
- การใช้ `http://` ในวง LAN ส่ง API Key แบบไม่เข้ารหัส เหมาะกับเครือข่ายที่เชื่อถือได้เท่านั้น
  ถ้าเปิดออกอินเทอร์เน็ตต้องใช้ `https://` (รองรับแล้ว ดู `certs.h` และ `TLS_VERIFY_CERTIFICATE`)
